# Helper Control-Auth Contract

## Problem

Dashboard mutations (`/control/<service>/<action>`, whitelist add/remove) go through `helper/uploader.py` behind Nginx. Authorization is `CONTROL_TOKEN` compared to `X-Control-Token` or a `token` query argument; if the token is unset, `_authorized` **denies**. The helper container also mounts `/var/run/docker.sock`, so a leaked token is host-adjacent. `helper-contract-check` already expects unauthenticated POSTs to return 401.

Stage 5 covers allowlist/control-plane files. Stage 7 covers `/status/full` JSON shape. Stage 13 covers day-to-day whitelist CLI. Contributors still need an **auth contract** so PRs do not add cookie SSO, put the token in GitHub issues, or accept empty tokens “to make demos easier.”

## Existing scan (reuse first)

| Asset | Role |
|---|---|
| `helper/uploader.py` `_authorized()` | Token compare; deny if unset |
| `CONTROL_TOKEN` in `env.example` / Compose | Secret generated by `generate-secrets` |
| Nginx allowlist for control locations | Source IP gate **in addition to** token |
| Landing page token input | Operator pastes token locally; not a community login |
| `scripts/helper-contract-check.sh` | Unauthenticated POST → 401 |
| Stage 5 `control-plane-contribution-contract.md` (expected sibling) | Allowlist file and nginx include |
| Stage 7 `helper-api-contribution-contract.md` (expected sibling) | Status JSON compatibility |
| Stage 8 `secret-rotation-credential-hygiene.md` (expected sibling) | Rotating `CONTROL_TOKEN` |
| Stage 13 `ip-allowlist-day2-contract.md` (expected sibling) | `whitelist-*` commands |
| Stage 17 `helper-contract-check-contribution-contract.md` (expected sibling) | How to extend the 401 probe |

Out of scope:

- OAuth/OIDC/SSO as a prerequisite for LAN operators
- Publishing the token in README screenshots or issue templates
- Binding helper to `0.0.0.0` without Nginx
- Treating query-string `?token=` as the preferred long-term API (logs and Referer leak)

## Proposal

Publish a **helper control-auth contract** for PRs that change how control routes authenticate.

### Contribution lanes

| Lane | Where | Evidence |
|---|---|---|
| Token check | `_authorized` | Empty token continues to deny |
| Transport | dashboard JS / docs | Prefer `X-Control-Token`; treat query param as legacy |
| New mutating route | helper + nginx | Allowlist **and** `_authorized`; contract-check 401 |
| Read-only status | `/status/*` | Stay unauthenticated as today unless a new risk appears |
| Rotation | `generate-secrets` / docs | Stage 8 hygiene; dashboard re-paste |
| Socket | helper Compose mounts | docker.sock stays a privileged review item (Stage 18 hardening) |

### Rules

1. **Deny by default when `CONTROL_TOKEN` is empty.** Do not add a “dev open” bypass in committed Compose.
2. **Mutating routes need token + allowlist.** IP allowlist is not a substitute for the token; the token is not a substitute for the allowlist.
3. **Prefer headers over query strings.** New clients must send `X-Control-Token`. Do not add tokens to URLs in docs.
4. **Status GETs stay public-on-LAN** unless a PR documents why a new field is sensitive.
5. **Never log the token.** Redact headers and query strings in access logs and helper debug.
6. **Contract-check must keep unauthenticated POST → 401** when helper is up.
7. **GitHub remains intake.** Requests for Keycloak/Authelia in front of the dashboard stay Issues unless accepted.

### Suggested contributor checklist

```text
1. New POST/PUT/DELETE helper routes call _authorized
2. Nginx location stays inside the control allowlist
3. helper-contract-check covers the new route (401 without token)
4. Dashboard uses X-Control-Token, not a token in the URL bar
5. Docs never paste a real CONTROL_TOKEN
6. Coordinate token rotation with generate-secrets
```

### Framework reuse

| Need | Prefer | Avoid |
|---|---|---|
| Auth | Existing token + allowlist | SSO product for LAN control |
| Proof | `helper-contract-check` | Manual “it 401’d on my machine” only |
| Rotation | Stage 8 secret hygiene | Long-lived README example tokens |
| Status schema | Stage 7 helper API contract | Mixing auth into `/status/full` without need |

## Rollout

1. Publish this page under `suggestions/website/`.
2. Prefer **code**: deprecate query-string token in new dashboard paths; add contract-check cases for each mutating route.
3. Optional: Nginx `limit_req` on control locations (zone `api` already exists).

## Acceptance criteria

- [ ] Empty `CONTROL_TOKEN` remains deny-by-default.
- [ ] Mutating routes require token and allowlist.
- [ ] Header is the documented client method.
- [ ] Unauthenticated POST 401 remains a required check.
- [ ] Tokens are never committed or logged.

## Rollback

Revert helper/nginx/docs independently. Prior auth behavior returns. Docs-only publication needs no runtime rollback.

## Success metrics

- New control routes fail contract-check without a token.
- Fewer operators sharing tokens in public issues.
- Dashboard control keeps working after token rotation without SSO work.
